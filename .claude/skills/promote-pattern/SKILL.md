# promote-pattern — повтор → структура

Закрывает задачу пользователя (2026-06-15): «при постоянно повторяющихся ошибках либо режимах
работы по алгоритму — вносить правки в скиллы / создавать новые». Парная петля — `/fix-on-sight`
(пишет теги, которые этот скилл читает). Соглашение: `<корень миниядра>/memory/pattern-promotion.md`.

**Главный принцип:** чинить один класс ошибки в третий раз — это сигнал, что чинить надо не ошибку,
а **систему, которая её порождает**. Ручное суждение «кажется, это уже было» ненадёжно — повтор
должен быть **посчитан** по данным (трейсы), а не вспомнен.

## Когда срабатывает

- Ревизия (еженедельно / по запросу): «что повторяется», «разбери накопленные ошибки».
- Пользователь: «пора закодировать», «сделай скилл из этого», «промотируй паттерны».
- Проактивно: сам ловишь, что чинишь класс `<ключ>` в N-й раз или гоняешь один алгоритм руками.
- Ввод `/promote-pattern`.

**НЕ срабатывает:**
- Одиночный баг прямо сейчас → `/fix-on-sight`.
- Спуск до корня многослойного бага → `/deep-debug`.
- «Работает или декорация» → `/enforcement-audit` (если установлен).

## Цикл

```
[1] ПОСЧИТАТЬ — запустить счётчик, получить кандидатов (>= порога):
       python <корень миниядра>/scripts/pattern_counter.py --min <порог>
       (по умолчанию порог 3; для дорогих/outward-facing классов можно --min 2, см. ниже)
   ▼
[2] ОТФИЛЬТРОВАТЬ — для каждого кандидата проверить, не промотирован ли уже
       (секция «Журнал промоций» в `memory/pattern-promotion.md`). Промотированные пропустить.
   ▼
[3] КЛАССИФИЦИРОВАТЬ по виду тега → выбрать тип промоции (таблица ниже).
   ▼
[3.5] ВЫБРАТЬ СРЕДСТВО ПО ЛЕСТНИЦЕ — какой файл править, сказала таблица;
       насколько сильное средство брать, говорит лестница (см. ниже).
       Счётчик показывает колонку «момент»: класс с пометкой «НЕ НАЗВАН»
       не промотируется вовсе — сперва найти для него наблюдаемое событие.
   ▼
[4] РАЗВИЛКА — если выбор типа промоции mutually-exclusive с последствиями → delegate simulate-fork.
       Иначе — выполнить промоцию автономно (non-exclusive items — подряд).
   ▼
[5] ПРОМОТИРОВАТЬ — внести правку (см. типы). work-mode → новый скилл delegate skill-creator (если установлен; иначе см. запасной путь в таблице типов).
   ▼
[6] ДЕДУП — дописать в «Журнал промоций»: дата · ключ · повторов · решение · ссылка.
       Иначе тот же класс всплывёт кандидатом снова.
```

## Типы промоции (по виду + слою тега)

| Вид + слой | Промоция |
|---|---|
| `failure-mode` слой `skill` | правка соответствующего `SKILL.md` (+ антипаттерн в скилл) |
| `failure-mode` слой `hook` | правка хука (если у вас есть хуки Claude Code) + перепроверка срабатывания (`enforcement-audit`, если установлен) |
| `failure-mode` слой `code` | фикс в репозитории + тест против класса |
| `failure-mode` слой `memory` | memory-verify + апдейт памяти |
| `failure-mode` слой `env` | обёртка-скрипт / запись в доку окружения (папка ваших скриптов или справочный документ) |
| `failure-mode` дорогой, повторный | правило в `memory/rules.md` (не в `CLAUDE.md`: тот файл обновляется релизами, своё правило в нём заблокирует обновление): always-on (если каждый turn) или, если у вас есть хук-напоминание по триггерам, pull-on-trigger через него |
| `work-mode` | новый скилл через **skill-creator** (если установлен) или расширение существующего скилла. Без skill-creator: создать папку `.claude/skills/<имя>/SKILL.md` по образцу соседних навыков (frontmatter `name` + `description`, затем шаги) |

## Лестница средств — брать нижнюю применимую (добавлена 2026-09-04)

Таблица выше отвечает «какой файл править». Лестница — «насколько сильное средство».
Идти сверху вниз, останавливаться на первой применимой ступени:

| № | Средство | Что требует от агента | Когда применимо |
|---|---|---|---|
| 1 | Убрать развилку — неверный путь не нужен | ничего | ошибиться становится нечем |
| 2 | Перехват в момент — хук по признаку из `[момент]` (если у вас настроены хуки Claude Code; иначе — ступени 1, 3, 4) | ничего | момент назван и детектируем |
| 3 | Дорожка дешевле обходной — скрипт, обёртка, команда | выбрать её, когда видно | верный путь есть, но дороже неверного |
| 4 | Текст в память / `memory/rules.md` | помнить весь разговор | момент недетектируем в принципе |

**Отбор:** нет названного момента — четвёртая ступень тоже не берётся. Класс
возвращается в наблюдение, пока момент не найдётся. Правило, которое нельзя
привязать к событию, не исполняется, а вес у соседних правил отнимает: внимание
конечно, и свод из сорока строк работает хуже свода из десяти.

**Основание.** Замер 2026-09-01: класс без механической проверки дал 6 повторов
за сессию, классы с проверкой не дожили до последствий ни разу. Замер 2026-09-04:
правило «не писать код через heredoc» жило в памяти и нарушено в пятый раз, тогда
как правила с перехватом на `Write|Edit` в тот же день соблюдались; при этом
правило «завести трассу в начале» лежало прямо в контексте и тоже не сработало —
потому что «сразу» не событие. Отсюда: **строить проверку, а не усиливать формулировку.**

## Порог: логика, не квота

- Дефолт 3. **0 кандидатов = валидный результат** — ничего не выдумывать, не добирать до квоты.
- Для классов, которые **дорого стоят** (раздражают пользователя, ломают outward-facing, теряют время) —
  порог опустить до 2. Прецедент: правило языка ответа подняли в always-on после **2** повторов с интервалом. Решение о снижении порога — здесь, явно, не автоматизм.
- Режим обзора: вывод счётчика — это обзор, не приказ. Каждый кандидат подтверждается отдельным
  решением о промоции, не «всё подряд закодировать».

## Делегирование (НЕ дублировать)

| Шаг | Кому |
|---|---|
| [4] выбор типа промоции = взаимоисключающий с последствиями | simulate-fork |
| [5] work-mode → создание/правка скилла | skill-creator (anthropic-skills), если установлен |
| [5] failure-mode слой hook → перепроверка срабатывания | enforcement-audit, если установлен |
| правка памяти | дисциплина memory-verify (перед опорой на запись памяти — сверить с живым состоянием; записи памяти — снимок на момент записи) |

Этот скилл — **диспетчер промоции** (посчитать → классифицировать → промотировать → дедуп),
а не реализация каждого типа правки.

## Связь с контуром

`/fix-on-sight` пишет `failure-mode:`/`work-mode:` теги → `scripts/pattern_counter.py` считает →
`/promote-pattern` (этот скилл) промотирует. Полное соглашение и журнал: `memory/pattern-promotion.md`.

**Формат тегов** — как в `memory/pattern-promotion.md`; счётчик принимает `failure-mode: ключ` и ``failure-mode `ключ` ``.

## Антипаттерны

- ❌ Промотировать «по памяти» без прогона счётчика (повтор должен быть посчитан).
- ❌ Добивать до квоты при пустом результате (порог, не квота).
- ❌ Промотировать и не записать в журнал → класс всплывёт снова, бесконечный цикл.
- ❌ work-mode закодировать в скилл, дублирующий существующий (сперва проверить список скиллов).
- ❌ Молча переписать `memory/rules.md` или править `CLAUDE.md` (он принадлежит релизам) для дорогого класса без согласования (escalate с числом повторов).
