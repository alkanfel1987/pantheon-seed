# fix-on-sight — починил на месте, не потерял урок

Закрывает задачу пользователя (2026-06-15): «исправлять баги сразу после обнаружения».
Парная петля — `/promote-pattern` (мета-петля при повторах). Соглашение и связь петель:
`<корень миниядра>/memory/pattern-promotion.md`.

**Главный принцип:** баг, найденный по ходу другой задачи, чинится **в этот же заход** — но не как
слепая заплатка. Минимальный честный цикл: понять реальную причину → исправить → **проверить
прогоном** → записать класс ошибки тегом, чтобы повтор был виден `/promote-pattern`. Без тега
ошибка «починена и забыта», и контур промоции её не увидит.

## Когда срабатывает

- По ходу любой задачи всплыл **баг**: падение, exit≠0, неверный вывод, сломанный рендер/формат,
  ложный результат, регрессия.
- Нужно исправить **здесь и сейчас** (а не занести в бэклог).
- Ввод `/fix-on-sight`.

**НЕ срабатывает:**
- Баг **повторяется** / многослойный / фикс не держится → сразу `/deep-debug` (deep-debug-loop).
- «Это enforced или декорация?» → `/enforcement-audit`.
- Накопились повторы, пора в скилл/правило → `/promote-pattern`.
- Не баг, а новая фича → `obra-brainstorming` / `obra-writing-plans`.

## Цикл (5 шагов)

```
[0] СТОП-КЛАССИФИКАЦИЯ — это баг или ожидаемое поведение? тривиальный или нет?
   │
   ├─ тривиальный (опечатка, один escape, явный typo, ясная причина + быстрая проверка)
   │     → чиню сам, шаги [2]-[4]
   │
   └─ нетривиальный (причина неясна / многослойно / повторялось / долгая проверка)
         → делегирую deep-debug-loop, возвращаюсь к [4] за тегом
   ▼
[1] ПРИЧИНА ИЗ ФАКТА — снять реальную причину (лог / exit-код / stderr / сам вывод),
   │   НЕ из памяти/гипотезы (memory-verify). delegate obra-systematic-debugging Phase 1.
   ▼
[2] МИНИМАЛЬНЫЙ ФИКС — чинить причину, не симптом. Не расширять охват без спроса.
   ▼
[3] ПРОВЕРКА ОБЯЗАТЕЛЬНА — прогон в рабочем режиме ИЛИ симуляция. delegate verification-first.
   │   Нет способа проверить → задача поставлена плохо, уточнить. «Должно работать» ≠ проверка.
   ▼
[4] ТЕГ В TRACE — записать класс ошибки в секцию «## Паттерны (для промоции)» трассы сессии (`<корень миниядра>/memory/session_traces/`):
       - failure-mode: <ключ> — <описание> [слой: skill|hook|memory|env|external|code|judgment] [поймано: механика|сам|оператор] [момент: <наблюдаемое событие>]
   (ключ kebab-case, КЛАСС а не разовость; свериться с `scripts/pattern_counter.py --kind all` чтобы не расщепить класс)
```

### Шаг [0] — критерий «тривиальный»
Тривиально И-И-И: (а) причина видна сразу из факта; (б) фикс локальный (1 место); (в) проверка
быстрая и детерминированная. Если хоть одно нет → нетривиальный → `deep-debug-loop`.

### Шаг [3] — что считается проверкой
- Скрипт/команда: реальный прогон, exit-код + ожидаемый вывод (не только «не упало»).
- Формат/рендер (как Telegram-markdown): отправить/срендерить и посмотреть результат, не глазами по коду.
- Логика: тест или воспроизведение исходного триггера — баг больше не воспроизводится.

### Шаг [4] — зачем тег обязателен
Тег — это **ввод данных** для `/promote-pattern`. Один баг = одна строка. Если класс уже
встречался (видно по счётчику) — это сигнал, что пора не чинить в N-й раз, а промотировать:
после фикса упомянуть «класс `<ключ>` уже N-й раз — кандидат в /promote-pattern».

**`[момент]` — не украшение, без него класс не промотируется.** `/promote-pattern` берёт
средство по лестнице: перехват хуком возможен, только если названо **наблюдаемое событие**,
при котором ошибка становится возможной. Класс с пометкой «момент НЕ НАЗВАН» счётчик
показывает, но промоция его пропускает — даже до записи правила в память.

Момент — это то, что видно **снаружи**, в потоке действий, а не намерение:
- ✅ «запись файла с кириллицей, который прочитает не Claude, а другая программа»
- ✅ «возможность заявлена наружу, но ни один тест не импортирует её из собранного пакета»
- ❌ «когда тороплюсь» · ❌ «при невнимательности» · ❌ «сразу после начала работы»
  («сразу» — не событие, замер 2026-09-04).

**`[поймано]`** — кем обнаружено: `механика` (скрипт/хук/тест), `сам`, `оператор`. Поле
показывает, какие классы ловятся только человеком — это и есть дыры в механической проверке.

⚠ Формат сверять с `memory/pattern-promotion.md` — он источник правды, а не этот файл.
Прецедент 2026-09-06: здесь стоял формат без `[поймано]` и `[момент]`, теги писались
неполными и в контур не попадали.

## Предохранители (mahā-vrata)

- ❌ **Нет автокоммита.** Починил — показал, коммит только по явной просьбе (как и общая дисциплина).
- ❌ **Outward-facing фикс → подтверждение.** Если правка меняет то, что уходит наружу (письмо, пост,
  прод-конфиг, удаление/перезапись чужого файла) — сначала подтверждение.
- ❌ **Не чинить из памяти/гипотезы** — снять реальный факт (memory-verify, шаг [1]).
- ❌ **Не расширять охват** под видом «заодно поправлю» — лишнее в spawn_task / отдельную задачу.

## Делегирование (НЕ дублировать)

| Шаг | Кому |
|---|---|
| [1] механика причины (Iron Law, обратная трассировка) | obra-systematic-debugging |
| [3] план и факт проверки | verification-first |
| нетривиальный / повторяющийся / многослойный | deep-debug-loop |
| outward-facing развилка фикса | simulate-fork |

Этот скилл — **дисциплина «починил → проверил → тегировал»**, тонкая обвязка над перечисленным.

## Связь с контуром промоции

`/fix-on-sight` пишет теги → `scripts/pattern_counter.py` считает → `/promote-pattern` промотирует повторы.
Полное соглашение: `memory/pattern-promotion.md`.

## Антипаттерны

- ❌ Починить и не проверить («должно работать»).
- ❌ Починить, проверить, но не тегировать → повтор невидим, контур слеп.
- ❌ Тег с разовым ключом (`bug-2026-06-15`) вместо класса (`telegram-markdown-escape`).
- ❌ Чинить N-й повтор как новый баг, не подняв `/promote-pattern`.
- ❌ Заплатка симптома вместо причины (это уже территория deep-debug-loop).
